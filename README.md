## 极简嵌入式项目
+=============================+
##### 对应芯片：STM32H750VBT6.
##### 已实现了：bootloader和分区A，简单的分区判断跳转逻辑. 是分区的简单实践.
##### 项目特点：项目从零搭建，文件数量极简，仅包含库文件、startup启动文件、ld链接文件、用户主程序文件，以及用来构建的makefile，不存在类似keil的工程，有助于理解底层.
+=============================+

###### （目录下还有一个文件夹Drivers，里面是两个库文件夹——CMSIS和HAL，均来自官方固件包.）
###### （固件包地址：```https://github.com/STMicroelectronics/STM32CubeH7```）

- 使用方法：
- 首先恢复`Drivers\`文件夹. 直接将固件包下载，里面的`Drivers\`文件夹拖到项目根目录，和`Core\`等目录平齐
- 对两个分支分别使用`make`，会得到两个不同的`bin`固件文件。
  - 烧录前要先合并两个固件文件，方法理解如下：
  - 合并的固件本身要烧到芯片地址空间`0x08000000`开头的位置。这个位置需要是`bootloader`分支固件的起始位置。也就是说，上电后，硬件首先读取这个地址的固件。
  - 另外的分区固件本身要放在地址空间`0x80020000`开头的位置。这个位置需要是`     app    `分支固件的起始位置。也就是说，`bootloader`逻辑中，跳转分区时会跳转这个地址，访问分区固件。
- 烧录后达到这样的效果，以下是`flash`的框图：
```
┬  +---------------------------+ ->  虚拟地址空间 地址0x0800_0000 （flash 在地址空间的映射起始位）
|  |         Bootloader        |
|  |---------------------------|
|  |                           |
|  |       空白区(0xFF填充)     |
|  |                           |
|  +---------------------------+ ->  虚拟地址空间 地址0x0802_0000
|  |           App区           |
↓  +---------------------------+
```
- 所以需要使用合适的方式，将两个固件文件的二进制连接起来，中间填充合适数量的0xFF，让app分区固件的开头地址达到预定偏移位置。
###### 具体合并代码不给出
###### _以上固件放置地址是写死的，如果芯片不同极可能不能用。项目仅做为参考学习。_
